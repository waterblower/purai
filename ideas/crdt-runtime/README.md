# CPU / CRDT / 内部计算原型

这是按照三个目标重新搭建的独立原型：CPU 友好、严格的状态型 CRDT
合并语义、内部计算量不受输出长度限制。现有 `../deno-version/` AFRN 与
TinyStories 结果仍可作为基线。

当前实现验证运行架构，不是新的 TinyStories
语言模型。它用两个从样本构建的有限转移表，加上手写循环程序，回答：**两个十进制整数之和能否被
3 整除？** 答案始终只有 `0` 或 `1`。

## 运行

需要 Deno；没有外部依赖。在本目录运行：

```sh
deno task check
deno task test
deno task demo

deno task run --model artifacts/merged.state.json --a 999 --b 3 --budget 2048
deno task run --model artifacts/merged.state.json --a 999 --b 3 --budget 8

deno task merge artifacts/replica-a.state.json artifacts/replica-b.state.json -o artifacts/remerged.state.json
```

`demo` 会实际生成三个可加载的模型快照：

- `artifacts/replica-a.state.json`：加法技能。
- `artifacts/replica-b.state.json`：余数技能。
- **`artifacts/merged.state.json`：合并后的模型**。

快照是带版本和内容哈希的规范 JSON，不使用旧 AFRN 的 `model.data`
二进制格式。它们可由 demo 重建，默认被 Git 忽略；测试结果保存在
[artifacts/RESULTS.md](artifacts/RESULTS.md) 和
[artifacts/results.json](artifacts/results.json)。

CLI 输出诊断 JSON，`prediction` 字段才是固定长度的答案。`source: "computed"`
表示程序到达 `emit`；`source: "prior"`
表示预算不足、缺少技能或其他执行失败后返回的明确标记的猜测。猜测取余数表最常见输出元组中的布尔分量，没有该表则取
`0`。它不是校准过的最终任务概率。请同时检查 `completed` 和 `status`。

## 三层结构

```text
副本 A 的模块 + 观测 ─┐
                     ├─ 集合并集 → 不可变知识状态
副本 B 的模块 + 观测 ─┘                  │
                                     确定性编译
                                         ↓
                               转移表 + 按输入行选择的专家
                                         │
                                     绑定程序端口
                                         ↓
输入 → 请求独立的寄存器/向量 → 有预算的循环执行 → emit → 答案
```

### 1. 持久知识：真正的 G-set CRDT

[src/knowledge.ts](src/knowledge.ts)
存储三类不可变记录：表模块、程序模块、训练观测。记录 ID 是规范化内容的
SHA-256；模块引用内容 ID。新观测通过增加记录提交，不原地修改计数。

状态的偏序是集合包含关系，合并是并集，因此满足交换律、结合律、幂等律，局部更新只增加状态。两份重叠快照反复同步不会重复计票。相同记录集合产生相同快照和派生执行视图，前提是副本使用同一版编译规则。

观测的逻辑身份是 `(module ID, event ID)`：

- 同一事件原样重发只保留一次。
- 独立观测即使输入和标签相同，也应该使用不同事件 ID，例如持久化的
  `replica UUID / sequence`。
- 同一事件出现不同内容时，所有版本仍保留在集合中，但编译器隔离这个事件，不让任何版本投票。
- 引用的模块尚未到达时，观测暂缓生效；模块后来合并进来即可激活。
- 输入/输出超出模块声明域的观测不参与训练，并计入诊断。

当前只有内存状态的并集与磁盘快照工具，没有网络同步协议。内容哈希保证内容校验和寻址，不提供作者认证。尚未实现删除、垃圾回收或有界存储；直接删掉旧观测会破坏当前
G-set
协议。并集收敛也不保证预测质量单调提高，或保证任意学习算法与集中式训练等价。

### 2. 编译视图：有限域学习与局部路由

[src/compile.ts](src/compile.ts)
从去重后的观测重建计数。每个专家的每一输入行选择多数输出；相同端口的多个专家按该行的
Laplace 平滑置信度选择一个，平票按内容 ID
排序。比较置信度时使用整数交叉相乘，避免浮点平票差异。这个路由规则是原型启发式，不是经过校准的可靠性估计。

编译后，每个端口有紧凑的 typed-array
转移表和来源索引。每个模块调用只访问对应输入行；模型中无关的专家不增加该次调用的扫描量。编译会扫描知识集合，消耗与模型规模相关的时间和内存；这种成本没有消失，只是移出了逐次查询路径。

编译视图可以随新证据改变，也可以重新生成；它不是需要 CRDT
合并的权威状态。合并新知识后需要重新编译并创建新的执行器。既有请求继续使用旧视图。

### 3. 执行器：内部状态与输出解耦

[src/vm.ts](src/vm.ts) 提供 16 个整数寄存器、4 个向量、条件跳转、专家调用和显式
`emit`。程序端口预先绑定，专家调用无需全库搜索。请求的工作内存可以覆盖和删除，与共享
CRDT 状态分离。

每条指令花费一个预算单位。预算耗尽会保留工作区，`Machine.advance(extraBudget)`
可继续执行；无限循环也受预算限制。程序到达 `emit`
才完成，内部循环不会生成解释文字或中间
token。预算是指令数，不是墙钟时间限制；输入解析、知识编译、加载及诊断序列化不计入预算。向量容量限制为
65,536 元素，示例每个输入最多 4,096 位。

## 本轮实验说明

[bench/fixtures.ts](bench/fixtures.ts) 创建两个独立副本：

- A 学习全部 200 个 `(数字 a, 数字 b, 进位) → (和的个位, 新进位)` 转移。
- B 学习全部 30 个 `(余数, 数字) → (新余数, 是否为零)` 转移。

两个副本共享 [src/example.ts](src/example.ts)
的手写程序：逐位加法，保存和的数字，然后逐位更新余数，最后输出布尔值。推理 VM
不内置加法或取模求解器；改变训练标签会改变最终答案，测试覆盖了这一点。训练生成器及评估
oracle 中的算术与推理代码分离。

两张表的有限输入域被完全枚举，因此这不是对未见原子转移的泛化实验。较长数字上的组合与循环没有作为完整任务训练，但其控制结构是人工给定的。能外推长度依赖这个程序结构，不应归因于自动程序发现。

评估使用固定随机种子，在 1、2、4、8、16、32、64、128
位这八组长度中分别平衡两类标签，共 1,024
个任务。不同预算使用相同任务。报告同时记录准确率和完成率，避免把猜对的未完成计算当成推理成功。这里更多预算允许更多任务完成，并未实现对同一未完成任务逐步改善猜测的
anytime 算法。

测试还验证了：合并代数性质、重复投递、事件冲突、乱序到达、确定性路由、输入校验、4096
位进位、预算约束与恢复、证据变化影响预测、推理不改变知识状态。

## 实测与限制

本机首轮结果：12 个测试通过；预算为 8 / 32 / 128 / 512 / 2048 时，准确率为 50% /
58.50% / 75% / 87.50% /
100%，答案长度始终一个字符。两个副本单独不能完成组合，合并后不再训练即可完成。

合并快照 55,526 字节，包含 233 条记录；两张执行表的 typed arrays 共 2,070
字节，**不包含** JS
对象、索引、程序、来源字符串或请求工作区。暖机后的混合长度查询约 69,411
次/秒，p50 7.21 µs、p95 51.67 µs；这是单次本机测量。原生 BigInt
参考实现明显更快，说明解释器与通用执行机制存在开销。此结果仅证明这个小原型能在
CPU 上轻量运行，尚不能证明大模型规模的 CPU 效率或相对于 LLM 的优势。

主要未解决问题是**怎样自动学到可复用程序，以及怎样在大型知识集合中经济地发现、选择和维护模块**。当前还没有程序综合、文本建模、语义表示学习、动态预算策略、分布式存储压缩或知识遗忘机制。

下一步应固定这三层接口，先让系统从完整任务样本中搜索短程序，而非继续手写每个任务的控制流；保留人工程序作为上限基线。然后再决定文本压缩/预测任务需要什么端口和表示，而不是把本次算术成功视为
TinyStories 已获改善。

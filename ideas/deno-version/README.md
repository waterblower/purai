# AFRN PoC（Deno / TypeScript）

`../topic.md` 第 7 节阶段 2 的实现：一个不用梯度、不用矩阵乘法的字节级语言模型。
模型是"代码 + 数据库"的镜像：代码是一个内容寻址的 Merkle DAG（`seq` / `alt` / `ctx` 三种节点），
数据库是挂在节点上的可加计数，外加两张可加的校准表。训练就是用 MDL 判据不断往镜像里加节点。

## 用法

```sh
deno task build                  # 编译出 ./train ./infer ./eval ./inspect ./merge ./unlearn（首次需要联网下载 denort）

./train training-data.txt -o model.data                        # 约 2 分钟（单线程）
./train act1.txt act2.txt act3.txt -o model.data               # 多篇文档：之后可以精确遗忘任意一篇
./infer --model model.data --input "ROMEO:" --n 300 --stats
./infer --model model.data --input "ROMEO:" --n 20 --trace     # 每一步用了哪些上下文、match 是否命中
./eval  --model model.data --text training-data.txt            # 末尾 10% 上的 bits-per-byte
./eval  --model model.data --text training-data.txt --no-match # 关掉 match 模型做对比
./inspect model.data                                           # 学到的词首片段、类、上下文
deno task visualize model.data                                 # 生成静态 model.html（可加 --text 文件 --prompt 开头）

./merge a.data b.data -o ab.data                               # CRDT 合并（参数不同会拒绝）
./unlearn ab.data b.data -o a-again.data                       # 精确减去 b 的全部证据
./unlearn model.data --text act2.txt -o forgot.data            # 减去一篇训练文档的贡献

deno task test                                                 # 15 项定律测试
deno task ngram training-data.txt 5                            # n-gram 基线（同样的平滑）
```

不编译也可以直接用 `deno task train training-data.txt` 等。

| `src/mdl.ts`           | Pitman-Yor 码长、结构码长                                             |
| `src/predict.ts`       | Pitman-Yor 平滑、按计数表混合、match 校准、采样                       |

## 每个字节的推理过程（全部是 CPU 擅长的操作）

1. **上下文匹配**：从根开始，沿上下文树向左做指针跳转和字节比较，找出所有被激活的 `ctx`。
2. **平滑**：每个 ctx 的分布是 Pitman-Yor 形式 `(max(c−d,0) + (θ+d·u)·P_父) / (N+θ)`，已经预先算好。
3. **混合**：叶子按权重 `2^(−κ·平均码长)` 线性混合。"平均码长"来自校准表，是这一类叶子（按深度和证据量分桶）在训练中的实际表现。
4. **Match 模型**：用哈希表加指针，在**当前输入的前文**里找最长匹配，提出"上次这之后是什么"。它的可信度由第二张校准表给出（按匹配长度和上下文模型的概率分桶）。这就是离散版的归纳头：in-context copy，每个字节 O(1)。

没有矩阵乘法，也没有浮点权重训练。`--stats` 能看到每个字节的计算步数（3 到几百步不等）。

## CRDT 性质是怎么保住的

所有可学习的状态都是**整数计数**：

- ctx 计数、seq 频数；
- 两张校准表，存为整数。码长以 1/1024 比特为单位取整以后再累加，所以加法满足结合律，结果逐位精确。

校准表按**文档内预序**统计：每个位置只用这篇文档中它之前的数据来"考"模型。所以一篇文档的贡献只取决于"代码 + 这篇文档"，这带来两个结果：

- `count(A) + count(B) = count(A, B)`，逐位成立；
- 删除一篇文档的贡献，结果与从来没见过它逐位相同。

解释器参数（d、θ、κ）决定了校准表的含义，所以参数不同的模型拒绝合并。

## 实测结果（Tiny Shakespeare，1.1MB；前 90% 训练，末尾 10% 验证）

| 模型                                         | valid bpc | 上下文数                            |
| -------------------------------------------- | --------- | ----------------------------------- |
| order-3 n-gram（Pitman-Yor 平滑）            | 2.574     | 11,228                              |
| **order-4 n-gram（Pitman-Yor，最好的基线）** | **2.425** | 48,539                              |
| order-5 n-gram（Pitman-Yor）                 | 2.450     | 133,293                             |
| 上一版 AFRN                                  | 2.551     | 9,381                               |
| AFRN，只有上下文树（`--no-match`）           | 2.320     | 56,132                              |
| AFRN，不用 Fold（`--folds 0`）               | 2.211     | 41,772                              |
| AFRN，不压缩（`--no-compact`）               | **2.207** | 56,132（其中 852 个类）             |
| **AFRN 默认参数（含观察等价压缩）**          | 2.217     | 50,104，步数/字节 35（不压缩时 99） |

训练 20 轮，共约 2 分钟（M 系列 Mac，单线程）。模型文件 924KB。推理约 300KB/s。

**各项改动的贡献**（同一份验证集）：

| 改动                                                                                                          | bpc           |
| ------------------------------------------------------------------------------------------------------------- | ------------- |
| 上一版                                                                                                        | 2.551         |
| + Pitman-Yor 平滑、计数表混合、match 模型                                                                     | 2.357         |
| + MDL 改用 PY 边际似然、θ=2、min-count 2、候选池从每轮 6000 扩到 200000（候选池是主要瓶颈），结构码长权重 0.1 | 2.223         |
| + 结构码长权重 0（只用 PY 边际似然）                                                                          | 2.207         |
| 其中 match 模型的贡献（关掉它时）                                                                             | 2.320 → 2.207 |

合并实验（前一半、后一半各训练一个模型，分别在各自那一半的末尾评估）：

| 模型          | A 尾部 bpc | B 尾部 bpc |
| ------------- | ---------- | ---------- |
| 只训练 A      | 2.182      | 2.513      |
| 只训练 B      | 2.257      | 2.307      |
| `merge(A, B)` | **2.119**  | **2.260**  |

`merge(A,B)` 与 `merge(B,A)` 逐字节相同；`unlearn(merge(A,B), B)` 与 A 逐字节相同。

## 观察等价压缩（训练结束时自动执行，`--no-compact` 关闭）

计数逐字节完全相同的上下文，在训练数据上行为一致，通常是同一组位置的不同写法（`[king]`、`[kin]['g']`、`[␣][k][i][n][g]`）。压缩只删除其中的"叶子"（没有子上下文、不是别人的先验），不改任何计数，所以 `merge` / `unlearn` 不受影响；之后再完整计数一遍，让校准表对应新结构。

| 配置                            | 删除      | valid bpc  | 步数/字节 | 文件       |
| ------------------------------- | --------- | ---------- | --------- | ---------- |
| 不压缩                          | 0         | 2.2070     | 99.0      | 924 KB     |
| 证据 ≥ 2，保留最浅              | 37,060    | 2.2673     | 79.5      | 380 KB     |
| 证据 ≥ 2，保留最深              | 37,019    | 2.2626     | 20.2      | —          |
| **证据 ≥ 20，保留最深（默认）** | **6,028** | **2.2167** | **35.4**  | **838 KB** |

- 证据少时"计数相同"常常只是巧合，合并它们会损失泛化，所以默认只合并证据 ≥ 20 的组。
- 保留最深的写法：浅层的词首片段上下文挂在根附近，每个位置都要测试，删掉它们省下的步数最多。
- 结论：用 0.4% 的 bpc 换来约 **2.8 倍**的推理计算量下降。想要最低 bpc 就用 `--no-compact`。

## 老实说，目前的状况

1. **超过了同等平滑的 n-gram 基线**：2.207 对 2.425。只用上下文树（不用 match）也超过了（2.320）。但 match 模型可以使用整段前文，而 n-gram 只看 4 个字节，这一部分优势来自机制本身，不是结构学习。
2. **Fold 的贡献仍然很小**（2.211 → 2.207）。泛化仍然是最难的部分。
3. **结构码长被关掉了**（`structWeight=0`）。只用 PY 边际似然的数据项效果最好：它本身就是贝叶斯模型比较，自带 Occam 惩罚。加上结构码长以后，模型更小但 bpc 更差（权重 1 时是 2.46）。所以现在的结构码长估计显然偏高，还没有一个自洽的"总码长"。
4. **Chunk 仍然是频率启发式。**
5. **合并不等于集中训练。** 只在一边出现的上下文，只带着那一边的证据。不过实测合并模型在两边都比单个模型好。
6. **校准表是"代码的函数"。** 合并两个结构不同的模型以后，校准表是两边统计的和，而不是对合并后的结构重新统计。要得到最准确的表，可以用原始数据 `recount` 一次。
7. **参照**：nanoGPT 的小 Transformer 在同样的切分上大约 2.1 bpc（凭记忆，没有在这里复现），它能看到 256 个字符的上下文。

## TinyStories：10 MB 子集实验

使用原始 TinyStories 的固定前缀：11,459 篇训练故事（正文约 10 MB），另用官方验证集的 1,286 篇故事（约 1 MB）。训练故事以空行连接，验证时逐故事重置状态；默认参数训练 20 轮，模型源码未改动。下表是最终压缩、重新计数后的模型结果，单位为 bits per byte（越低越好）。

| 配置 | 验证 BPB |
| --- | ---: |
| n-gram，8 字节上下文（测试 0–10 阶中最好） | **1.3148** |
| AFRN 默认 | 1.3447 |
| AFRN 关闭 match | 1.3756 |
| AFRN 关闭 Fold | 1.3435 |

这次配置下，AFRN 未超过最好的 n-gram 基线；match 有帮助，Fold 没有显示收益。固定提示词生成的样本能复现故事中的常见短语，但有明显语法错误、人物切换和情节不连贯，尚不能稳定生成完整故事。这些结论只针对本次 10 MB 子集和训练设置。

默认模型为 `bench/results/tinystories10mb/default.data`（2,241,880 字节），对照模型为同目录下的 `no-fold.data`。原有根目录的 `model.data` 没有覆盖。
